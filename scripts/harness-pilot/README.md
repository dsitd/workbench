# Переносимые бенчмарки Workbench

Node.js 22.12+ и Python 3; macOS использует sandbox-exec, Ubuntu/Debian — Bubblewrap. Полные зависимости: [docs/linux.md](../../docs/linux.md).

## Бесплатные проверки

```sh
npm run bench:check
npm run bench:memory -- --dry-run --arms workbench
```

`bench:check` создаёт собственное временное задание и проверяет настоящий цикл агента: чтение, правку, команду и автоматическую проверку результата. Ответы модели локальные; ключ не требуется.

Memory replay использует синтетическую историю. В dry-run ответы являются заглушками, поэтому оценка 0/24 ожидаема и не оценивает качество модели. Проверяется работа транспорта, суммаризации и продолжения.

## Задания из манифеста

```sh
npm run bench -- --dry-run --arms workbench --base /absolute/path/fixtures --manifest /absolute/path/fixtures/manifest.json
```

Базовая структура данных:

```text
fixtures/
  manifest.json
  dataset/
    sample-task/
      sample_task.py
      sample_task_test.py
      .docs/instructions.md
```

Минимальный манифест: `{"tasks":["sample-task"]}`. По умолчанию разрешённый файл решения получается заменой дефисов на подчёркивания и добавлением `.py`. Поле `taskFiles` может указать другие файлы. Grader восстанавливает исходные тесты отдельно, переносит только разрешённые решения и проверяет непредусмотренные изменения. Для существующих diverse/SWE-манифестов нужны их отдельные hidden fixtures и закреплённый runtime; данные чужих экспериментов в репозиторий не включены.

## Сравнение с Pi

Установите публичный пакет в отдельный каталог, не содержащий пользовательских профилей:

```sh
npm install --prefix .workbench/comparison/pi @earendil-works/pi-coding-agent@1.1.0
npm run bench:memory -- --dry-run --arms workbench,pi
```

Можно задать `--pi-dir /absolute/path` с установленным пакетом, `--node`/`--python` для интерпретаторов и `--swe-runtime` для SWE. Зависимости устанавливаются заново для каждой ОС. В Linux Pi соединяется только с бюджетным шлюзом через Unix-сокет и relay внутри изолированной сети.

## Реальные запросы

Без `--dry-run` возможны платные обращения. Нужны отдельно разрешённый пользователем бюджет, накопительный реестр расходов и поддерживаемый профиль модели. Числа в исторических бюджетных модулях не являются новым разрешением на расходы. Резервы неизвестных запросов сохраняются между запусками.

Под Node пользователь указывает только имя переменной: `--credential-env OPENROUTER_API_KEY`. Значение остаётся в родительском шлюзе и не передаётся дочерним процессам. Скомпилированный runner под Electron может использовать системное хранилище Workbench. Dry-run vault не открывает.

Для сопоставимости фиксируйте задачи, модель, версии интерпретаторов и лимиты. ОС и архитектура записываются в новые отчёты. Исторические результаты, приватные бюджеты и разовые контроллеры кампаний здесь не публикуются; сохранены только необходимые модули и тесты бюджетов.
