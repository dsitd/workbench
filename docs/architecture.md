# Архитектура Workbench

Workbench — приложение Electron для macOS. Основной процесс хранит локальные данные и выполняет разрешённые операции, интерфейс React работает через типизированный IPC. Запросы к моделям идут из приложения напрямую к настроенному API.

## Модули

| Каталог | Ответственность |
| --- | --- |
| `src/main` | Запуск Electron, preload/IPC, хранилище, ключи и жизненный цикл приложения. |
| `src/backend` | Проекты, файлы, команды, MCP, skills, снимки и проверка прав. |
| `src/agent` | Цикл агента, подготовка контекста, протоколы моделей, бюджеты и контроль завершения. |
| `src/renderer` | Проекты, чаты, настройки, редактор, изменения и журнал запусков. |
| `src/shared` | Общие типы, схемы инструментов и правила валидации. |
| `src/evals` | Изолированные локальные проверки поведения приложения. |

`src/agent/index.ts` управляет жизненным циклом запуска в чате. `src/agent/runtime.ts` содержит рабочий цикл. Адаптеры провайдеров, контекст, исполнение инструментов и проверка результата выделены в отдельные модули.

## Выполнение задачи

1. Runtime загружает проект, модель, настройки, историю и разрешения.
2. Контекст включает правила проекта, выбранные skills, файлы, доступные инструменты и историю в пределах окна модели.
3. Провайдер возвращает текст и вызовы инструментов. Аргументы проверяются по схеме, а доступ — повторно перед исполнением.
4. Независимые чтения могут выполняться параллельно. Записи, команды и другие операции с возможным побочным эффектом сохраняют необходимый порядок.
5. Каждый объявленный tool call получает результат с тем же ID, включая ошибку или отмену. Расходы, результаты и состояние задачи сохраняются в журнале.
6. Перед завершением проверяются зарегистрированные критерии, свежесть доказательств и неопределённые операции. Настроенная проверка проекта выполняется согласно настройкам пользователя.

Остановка отменяет запрос модели, текущие операции и ожидание подтверждения. Продолжение использует сохранённые результаты; неизвестный исход действия требует проверки перед повторением. Несовместимые сохранённые запуски отклоняются до отправки запросов и изменений.

## Контекст и расходы

Контекст ограничен окном выбранной модели, запасом на ответ и пользовательским пределом, если он задан. При заполнении окна может выполняться модельная суммаризация. Полная история, заметки, критерии задачи и журнал действий сохраняются локально.

Отбор контекста использует пути, слова задачи, сигнатуры кода и доступные зависимости. Полного семантического индекса проекта нет. Оценка токенов до запроса эвристическая; фактический usage приходит от провайдера.

Бюджеты ограничивают шаги, токены, стоимость и длительность. Расход суммаризации и вспомогательных запросов учитывается отдельно. Неизвестная стоимость отображается явно и не считается нулевой.

## Доступ и данные

Файловые операции проверяют канонические пути, символические ссылки и права на вложенные папки. Команды используют `sandbox-exec`; при недоступности изоляции они не запускаются. Удалённый MCP-сервер выполняет действия в своём окружении: локальные права папок не ограничивают его аккаунт.

API-ключи вводятся пользователем и хранятся отдельно в зашифрованном виде. История, вложения, настройки и снимки находятся в каталоге данных приложения. Их нет в репозитории. Вывод инструментов и внешние документы рассматриваются как данные, а не источник новых разрешений.

## Проверка

`npm run check` проверяет типы, запускает локальные тесты и собирает приложение. Тесты используют временные папки и подставные ответы API. `npm run smoke` проверяет интерфейс Electron, а `npm run sandbox:check` — реальную изоляцию команд; эти команды запускаются из обычного macOS Terminal.

Успешные проверки подтверждают соответствующие контракты приложения. Они не гарантируют правильность любого ответа модели. Объявленные критерии задачи и тесты также могут быть неполными.
