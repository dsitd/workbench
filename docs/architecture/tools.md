# Инструменты агента

[Общая архитектура](../architecture.md) · [Память и контекст](memory.md) · [Цикл выполнения](execution.md)

Инструмент имеет имя, описание, JSON Schema аргументов и класс разрешений. Модель видит только каталог текущего шага. Схема не даёт права на выполнение: runtime и backend повторно проверяют аргументы, режим чата и доступ проекта.

## Где определяется каталог

| Уровень | Реализация | Что содержит |
| --- | --- | --- |
| Нативные операции | [backend/tools.ts](../../src/backend/tools.ts) | Файлы, поиск, команды, web, изображения, процессы. |
| История и квитанции | [backend/context-tools.ts](../../src/backend/context-tools.ts) | История чата, сохранённый вывод, исходы операций. |
| Управление задачей | [agent/runtime.ts](../../src/agent/runtime.ts), [task-contract.ts](../../src/agent/task-contract.ts) | План, критерии, notes, проверка и завершение. |
| Внешние операции | [backend/mcp/index.ts](../../src/backend/mcp/index.ts) | Только включённые пользователем инструменты серверов, доступных проекту. |

`WorkspaceServices` собирает определения и обработчики в `ToolRegistry`. Runtime добавляет собственные инструменты и применяет фильтры режима, интернета и discovery. Определение без обработчика, неправильная схема или конфликт имени отклоняются при регистрации.

## Файлы, поиск и изображения

| Инструмент | Назначение | Существенный контракт |
| --- | --- | --- |
| `list_files` | Корни проекта или содержимое разрешённой папки. | Наличие имени credential-файла в списке не разрешает его чтение. |
| `read_file` | Текст файла целиком или по строкам `startLine/endLine`. | Возвращает версию файла; существующий файл нужно прочитать перед правкой. Файл до 2 MiB, вывод сервиса ограничен. |
| `search_files` | Literal/regex-поиск через ripgrep, glob, регистр и соседние строки. | Исключает защищённые файлы, зависимости, сборки, бинарные и слишком большие файлы; поиск не заменяет read-before-edit. |
| `write_file` | Создать или заменить текстовый файл. | Запись только в разрешённой папке; для существующего файла проверяется прочитанная версия, сохраняется снимок. |
| `edit_file` | Точная замена или пакет `edits`. | Все замены сопоставляются с исходной версией; пересечение правок отклоняет пакет. Неоднозначность требует `replaceAll`. |
| `read_skill_resource` | Прочитать текстовый ресурс установленного skill. | Относительный путь внутри включённого skill, доступного проекту; защищённые пути запрещены. |
| `list_attachments` | Получить страницу метаданных изображений чата. | Метаданные не отправляют модели байты изображений. |
| `inspect_image` | Выбрать вложение или импортировать изображение из проекта для просмотра моделью. | Учитываются доступ чата, поддержка vision и `detail`; повторный просмотр требует нового вызова. |

Реализация доступа и правок: [files.ts](../../src/backend/files.ts), [batch-edit.ts](../../src/backend/batch-edit.ts), [access.ts](../../src/backend/access.ts), [ripgrep-search.ts](../../src/backend/ripgrep-search.ts), [attachments.ts](../../src/backend/attachments.ts).

## Команды и web

| Инструмент | Назначение | Ограничение |
| --- | --- | --- |
| `run_command` | Команда с ограничением времени, выводом и наблюдаемым exit code. | macOS sandbox, разрешения пользователя, контроль прав и снимки допустимых текстовых изменений. |
| `start_background_command` | Управляемый фоновый процесс, возвращающий ID. | Поток вывода виден в UI; фоновые изменения не входят в обычный откат задачи. |
| `list_processes` | Статусы и вывод управляемых процессов чата. | Загружается через `load_workspace_tools`. |
| `stop_process` | Остановить управляемый процесс и его дочерние процессы. | Проверяется принадлежность проекту. |
| `typescript_diagnostics` | Проверить TS-проект его локальным компилятором. | Не устанавливает зависимости; не создаёт выходные файлы проекта; incremental-данные направляются во временную папку. |
| `web_search` | Поиск публичных страниц через DuckDuckGo HTML. | Требует интернета проекта; выдача считается недоверенными данными. |
| `web_fetch` | Получить читаемый текст публичной страницы. | Блокируются private/локальные адреса, credential URLs, неподходящий или слишком большой ответ. |

Сервисы: [commands.ts](../../src/backend/commands.ts), [processes.ts](../../src/backend/processes.ts), [diagnostics.ts](../../src/backend/diagnostics.ts), [network.ts](../../src/backend/network.ts). Это текстовые web-инструменты; управление произвольным графическим браузером или рабочим столом в этот каталог не входит.

## Задача, память и завершение

| Инструмент | Назначение | Когда доступен |
| --- | --- | --- |
| `update_plan` | Сохранить шаги `pending/running/completed`. | Добавляется runtime. Статус пункта плана не является доказательством выполнения. |
| `load_task_tools` | Выбрать схемы критериев и памяти для следующего запроса модели. | Добавляется runtime; новая выборка заменяет прежнюю. |
| `set_task_criteria` | Зарегистрировать критерии с точной цитатой запроса и способом проверки. | После `load_task_tools`; принятые условия нельзя удалить или ослабить. |
| `record_task_evidence` | Привязать наблюдение по `toolCallId` к одному или нескольким критериям. | После `load_task_tools`; результат должен быть успешным, актуальным и подходящим под `toolName/expectedText`. |
| `record_task_note` | Сохранить решение, ограничение, гипотезу, вопрос или следующий шаг с источниками. | После `load_task_tools`; [формат и жизненный цикл](memory.md#заметки-задачи). |
| `verify_project` | Выполнить или повторно использовать актуальную проверку проекта. | При настроенной команде и сервисе проверки, вне Plan. |
| `finish_task` | Передать финальный текст на приёмку runtime. | При включённой автоматической проверке и настроенной команде, вне Plan. Должен быть единственным вызовом в ответе. |
| `check_completion` | Вернуть недостающие критерии и неизвестные исходы. | Служебный вызов, который runtime сам добавляет при отклонённом завершении; не обычная команда каталога модели. |
| `explore_code` | Поручить отдельному контексту исследование кода. | Добавляется runtime; до 6 запросов выбранной модели в пределах бюджета родительской задачи. |

Класс `permission: read` у заметок и плана означает отсутствие записи в файлы проекта. Эти инструменты изменяют внутреннее состояние `RunRecord`, которое сохраняет приложение.

`explore_code` получает только `list_files`, `read_file`, `search_files`. Ему недоступны правки, shell, web, MCP, изображения и дальнейшее делегирование. Результат содержит выводы и ссылки на прочитанные файлы; чтение дочерним исследованием не удовлетворяет требование родителя прочитать файл перед изменением. См. [explore.ts](../../src/agent/explore.ts).

`behaviorVerification` добавляет к `run_command` описание проверки воспроизведения и регрессии. Настройка выключена по умолчанию и не заменяет обычные проверки проекта. Реализация: [behavior-verification.ts](../../src/agent/behavior-verification.ts).

## История, большие результаты и исходы действий

Эти инструменты загружаются через `load_workspace_tools`. Загрузка выбирает схемы на следующий шаг, ничего не исполняет и не расширяет права. Сохранённая выборка восстанавливается при продолжении; при неизвестных исходах runtime сам добавляет инструменты сверки операций.

| Инструмент | Что читает или меняет |
| --- | --- |
| `search_history` | Literal-поиск по публичному тексту сообщений текущего чата с выдачей ID и выдержек. |
| `read_history` | Сообщение по ID, с символьными `offset/length`. Не возвращает скрытые provider reasoning и произвольные чаты. |
| `search_tool_output` | Поиск в сохранённом большом результате по `resultId`. |
| `read_tool_output` | Диапазон сохранённого результата без повторного выполнения команды. |
| `get_operation` | Квитанция и статус действия по `operationId`. |
| `reconcile_operation` | Записать наблюдённый исход `confirmed/not-executed` со свежим `evidenceToolCallId`. Для `not-executed` требуется отдельное разрешение на повтор даже в Bypass. |

`messageId`, `toolCallId`, `resultId`, `operationId` — разные идентификаторы. Их берут из результатов соответствующих инструментов, а не конструируют из текста задачи. Смена области доступа делает недоступными старые результаты, notes и квитанции с несовпадающим scope.

## MCP discovery

При небольшом каталоге, до 8 внешних инструментов, полные схемы доступны сразу. При большем каталоге `find_mcp_tools` локально ищет по метаданным и выбирает до 8 схем на следующий шаг. Новая выборка заменяет прежнюю. Поиск не делает сетевых вызовов и не запускает сервер.

Пользователь сначала включает сервер, назначает проекты и разрешает конкретные tools. Discovery работает только внутри этого набора. При исполнении MCP manager повторно проверяет сервер, проект, имя, схему и правила подтверждения. `readOnlyHint` сервера сам по себе не даёт разрешение на вызов.

См. [tool-discovery.ts](../../src/agent/tool-discovery.ts), [workspace-tool-discovery.ts](../../src/agent/workspace-tool-discovery.ts), [MCP](../mcp.md).

## Порядок исполнения

Пакет модели не исполняется вслепую. Runtime проверяет имена, JSON-аргументы, доступность схем, актуальную конфигурацию чата и подтверждения. Некорректный JSON блокирует пакет действий; модель получает результаты с ошибками и может исправить вызовы.

Параллельно выполняются только соседние независимые нативные чтения `read_file/list_files/search_files/read_skill_resource`, до 4 одновременно. Другие вызовы образуют барьер. Результаты записываются в порядке объявлений, даже если чтения закончились в ином порядке. Это сохраняет пары assistant/tool и предсказуемую историю. [tool-scheduler.ts](../../src/agent/tool-scheduler.ts).

## Расширение

1. Определить `ToolDefinition`: уникальное имя, описание, JSON Schema и `permission`.
2. Реализовать обработчик `RegisteredTool<WorkspaceServices>`, использующий существующие сервисы доступа. Не обходить canonical-path, read-before-write и sandbox проверки прямой записью из обработчика.
3. Зарегистрировать инструмент в `WorkspaceServices.toolRegistry`; имена runtime и namespace `mcp_` зарезервированы.
4. Определить реальные эффекты: локальное чтение, запись, команда, сеть. Для действий проверить журналирование и восстановление после неизвестного исхода.
5. Проверить схему, запреты режима, отмену, ошибки и соответствие call ID результату. Образец: [backend-tool-registry.test.ts](../../tests/backend-tool-registry.test.ts).

Hooks `beforeTool`, `afterTool`, `finishTurn`, `beforeComplete` предназначены для доверенного кода интеграции. Они не являются устанавливаемыми текстовыми skills. Hooks получают копии наблюдений; ошибка не превращает уже выполненное действие в невыполненное. [hooks.ts](../../src/agent/hooks.ts).
