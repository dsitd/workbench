# MCP-серверы в Workbench

Workbench подключает инструменты Model Context Protocol через собственный агентный цикл. Протокол обслуживает официальный TypeScript client SDK; выбор контекста, разрешения, история и выполнение шагов остаются в нашем harness. Поддерживаются локальный **stdio** и удалённый **Streamable HTTP**.

## Подключение

1. Откройте **MCP-серверы → Добавить сервер**.
2. Выберите способ подключения. Для stdio укажите исполняемую команду и массив аргументов; для HTTP — полный URL MCP-endpoint.
3. Для OAuth оставьте Bearer-токен и имя его переменной пустыми. Для сервера с готовым Bearer-токеном либо stdio с переменными окружения заполните соответствующие защищённые поля. Существующие значения интерфейс не возвращает. В конфигурации сохраняются только имена переменных.
4. Отметьте проекты, включите сервер и сохраните конфигурацию.
5. Выберите проект для проверки и нажмите **Подключить и получить инструменты**. Эта кнопка запускает настроенную программу либо связывается с HTTP-сервером. Если HTTP-сервер требует OAuth, откроется системный браузер: завершите вход и выдачу доступа, затем вернитесь в Workbench. Кнопка «Отменить подключение» прерывает ожидание; общий предел — пять минут.
6. Отметьте нужные инструменты в полученном списке и сохраните. Новые инструменты автоматически не включаются.
7. Поставьте задачу в чате проекта. В режимах «Автопринятие правок» и «Каждое действие» MCP-вызов требует разрешения с сервером, инструментом и аргументами. В Bypass подтверждения пропускаются, в «Плане» MCP-вызовы отключены.

Типовая локальная конфигурация использует команду `npx` и аргументы вроде `["-y", "@modelcontextprotocol/server-filesystem", "/папка/проекта"]`. Проект должен иметь доступ к этой папке. Для загрузки пакета нужен интернет. Ввод команды и аргументов не является shell-скриптом: подстановки, пайпы и перенаправления не выполняются.

HTTP требует HTTPS; незашифрованный HTTP разрешён только для явно указанного loopback endpoint. Удалённое подключение требует включённого интернета проекта. Bearer-токен вводится отдельно от URL. URL с паролями, query-параметрами и fragments отклоняются; перенаправления не выполняются.

OAuth использует обнаружение Protected Resource Metadata и сервера авторизации, Dynamic Client Registration, Authorization Code с PKCE S256 и `resource` indicator. Ответ браузера принимает одноразовый listener на `127.0.0.1` со случайным `state`; issuer проверяет SDK. Client credentials и токены сохраняются только в зашифрованном хранилище и привязаны к точному URL MCP. Access/refresh tokens не передаются интерфейсу. После ответа 401 выполняется обновление токена; интерактивный вход запускается только из настройки подключения, а агент получает указание открыть настройки, если повторный вход необходим. Явно введённый Bearer-токен имеет приоритет над OAuth.

Для серверов, смонтированных под URL-префиксом, есть дополнительная проверка `<issuer-path>/.well-known/oauth-authorization-server`, если стандартное обнаружение не нашло документ или OIDC alias оказался неполным. Этот отдельный документ проходит штатную OAuth-схему и проверку issuer в SDK. Интерактивный вход выполняет пользователь.

Сетевые запросы OAuth отделены от запросов к ресурсу MCP: metadata и token endpoints могут находиться на другом публичном HTTPS-хосте. DNS проверяется и фиксируется для соединения, перенаправления с credentials запрещены. При выключенном интернете доступен только локальный OAuth для явно локального MCP. Состояние PKCE и discovery живёт только на время входа; незавершённый вход после закрытия приложения нужно начать заново.

## Границы доступа

- Сервер принадлежит только отмеченным проектам. Разные проекты получают отдельные соединения и доступ к своим папкам.
- Агент получает только сохранённые и включённые инструменты. Каталог перед каждым шагом обновляется без запуска программ и сетевых запросов. Схемы входят в бюджет контекста; одновременно разрешается до 64 MCP-инструментов на проект.
- Режим чата определяет необходимость подтверждения; `readOnlyHint` сервера является описанием и сам не отменяет подтверждение. В «Плане» MCP не исполняется: заявление сервера о чтении не доказывает отсутствие внешних изменений.
- Перед исполнением повторно проверяются проект, сервер, список инструментов и актуальная схема. Изменение схемы требует повторной проверки подключения.
- Локальная программа работает через macOS sandbox с папками и настройкой интернета проекта, отдельными HOME/TMP и ограниченным окружением. Приватные данные приложения и credential paths защищены. Если sandbox недоступен, stdio не запускается.
- Удалённый сервер исполняет действие на своей стороне; локальные права папок не ограничивают его аккаунт. Разрешение конкретного вызова определяет, что отправляется этому серверу.
- Сохранённые секреты привязаны к адресу сервера либо команде и аргументам. Правка адреса/программы не переносит прежний токен на новое подключение.
- Остановка задачи отменяет ожидающий вызов; выход из приложения закрывает соединения и локальные процессы. На объявленный call ID сохраняется результат либо ошибка.

В историю попадают ограниченные текстовые результаты и структурированные данные. Известные credentials и типовые секреты очищаются; сырой stderr и тела сетевых ошибок не отображаются. Описания и результаты MCP считаются внешними данными, а не инструкциями, меняющими разрешения приложения.

## Текущий объём поддержки

Поддержаны discovery и вызовы **tools** через stdio/Streamable HTTP, Bearer-авторизация, OAuth через браузер с динамической регистрацией настольного клиента и явно выбранные переменные окружения. Сервер OAuth должен разрешать public client, PKCE и loopback callback; предварительно зарегистрированные client ID и размещение Client ID Metadata Document пока не настраиваются. Старый HTTP+SSE transport, MCP Apps, подписки resources и отдельный каталог prompts пока не реализованы.

Реализация и тесты используют отдельное локальное состояние и тестовые серверы. `tests/mcp-oauth.test.ts` проверяет полный вход, PKCE, повторное подключение, refresh, неверный state/issuer и отмену. Проверка конкретного внешнего сервера требует его URL/команды и пользовательской авторизации.

Официальные источники: [TypeScript SDK v2](https://github.com/modelcontextprotocol/typescript-sdk), [MCP transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [подключение локальных серверов](https://modelcontextprotocol.io/docs/2026-07-28/develop/connect-local-servers).
